# Операторски интерфейс (LVGL 9)

Интерфейсът на контролера, написан на C с [LVGL](https://lvgl.io) 9.6.0 (MIT). LVGL е git подмодул в `lvgl/`, закрепен към версия `v9.6.0`. Еталонът за вида е `../maket.html`.

| Цел | Какво е | Изисква |
|---|---|---|
| `cnc-ui` | Linux платката (Orange Pi / Raspberry Pi): DRM/KMS за екрана, libinput за мишка и тъч, без X сървър | `libdrm-dev`, `libinput-dev` |
| `cnc-ui-sim` | симулатор в прозорец на компютър | `libsdl2-dev` |

CMake строи всяка цел, за която има библиотеки. На Orange Pi няма SDL2, затова се строи само `cnc-ui`.

## Orange Pi (Armbian Minimal)

Еднократно:

```sh
sudo apt install build-essential cmake pkg-config git libdrm-dev libinput-dev
sudo usermod -aG video,input $USER     # достъп до /dev/dri и /dev/input; излезте и влезте отново
cd ~/cnc-kontroler
git submodule update --init ui/lvgl/lvgl
cd ui/lvgl
cmake -B build -DCMAKE_BUILD_TYPE=Release
```

Всеки път след промяна:

```sh
cd ~/cnc-kontroler && git pull && git submodule update --init ui/lvgl/lvgl
cd ui/lvgl && cmake --build build
./build/cnc-ui
```

Първото компилиране на LVGL на Orange Pi One отнема няколко минути. `cmake --build build -j4` ползва и четирите ядра (при 512 MB RAM е безопасно за C).

- Програмата рисува директно на HDMI екрана. Пуска се от SSH, а изображението е на монитора. Спира се с Ctrl+C.
- Ако мониторът показва конзолата или графичен вход, програмата не може да вземе екрана. На Armbian Minimal няма графичен вход.
- Ако има няколко DRM устройства: `./build/cnc-ui --drm /dev/dri/card1` (или `CNC_DRM_DEVICE=/dev/dri/card1`).
- Мишката се търси при старта. Курсорът се рисува от LVGL.
- Ориентацията следва резолюцията на екрана. При 1920×1200 е хоризонтална, а при 800×1280 е портретна.
- Режимът на екрана: собственият DRM драйвер (`src/drm_disp.c`) взима режима от Настройки → Дисплей, а при „Автоматично“ предпочитания режим на монитора. Ако мониторът не го обяви (HDMI → DVI без EDID), има вградени стандартни режими (1920×1200, 1920×1080, 1680×1050 …).
- `./build/cnc-ui --modes` показва изходите и режимите, които мониторът обявява. `--mode 1920x1200` и `--rot 90` задават режима и завъртането еднократно.
- Ctrl+C спира програмата и връща конзолата.
- Автоматично пускане при старт: `sudo bash tools/cnc-ui-autostart.sh` (systemd услуга `cnc-ui`; `--off` я изключва). След обновяване: `sudo systemctl restart cnc-ui`; преди ръчно пускане: `sudo systemctl stop cnc-ui`.

## Симулатор

```sh
cmake -B build && cmake --build build
./build/cnc-ui-sim                       # 800×1280, портрет
./build/cnc-ui-sim --res 1920x1200       # като монитора за разработката
./build/cnc-ui-sim --res 1920x1200 --zoom 0.5
```

Снимка на екрана без прозорец (така се проверява всяка промяна в облачната сесия):

```sh
SDL_VIDEODRIVER=dummy ./build/cnc-ui-sim --res 1920x1200 --shot ekran.bmp
SDL_VIDEODRIVER=dummy ./build/cnc-ui-sim --res 1920x1200 --reset --after 1300 --shot homing.bmp
```

`--reset` натиска RESET в началото, а `--after` е след колко ms се прави снимката.

На Windows симулаторът е само по желание, през MSYS2 (`mingw-w64-x86_64-SDL2`, `cmake`, `gcc`).

## Мащаб и шрифтове

Както в макета: `em = min(W, H) / 800 × 16 px`. Всички размери в кода са `EM(x)`.

Шрифтовете са в две степени: `t16` за екрани с по-къса страна 800 и `t24` за 1080 и 1200. Изборът е при старта. Ако се добави екран с друг размер (например 600×1024), в `gen_fonts.sh` се добавя степен.

Шрифтове: Roboto Condensed (надписи), Roboto (текст), JetBrains Mono (числа). Barlow и Barlow Condensed от първоначалния план нямат кирилица (нито в Google Fonts, нито в хранилището на автора), затова са заменени. Шрифтът за буквите на осите (`ui_ax`) и за големите числа (`num_lg`) съдържа само нужните знаци, за да е малък.

Промяна на шрифтовете:

```sh
cd fonts && LV_FONT_CONV='npx lv_font_conv@1.5.3' sh gen_fonts.sh
```

## Какво има засега

Всички екрани на фрезата от макета, с демо модел на машината (без STM32):

- **Горна лента:** RESET, състояние, режим, вид машина, активна нула (и детайл k/n при няколко детайла), инструмент, MCU, съобщение или аларма, час, авариен стоп.
- **Работа:** позиции, 3D траектория, G-code списък, оверрайди, напредък, бутоните на цикъла, „Run from here“ (избор на ред, възстановяване на инструмента и оборотите).
- **Ръчно:** нулиране и „Задай“ за всяка ос, движение със стъпка или непрекъснато, скорост, реферирване с датчик или „Ръчно, тук“, траектория.
- **MDI:** команди (G0/G1, G90/G91, F, S, M3/M5, M8/M9, T M6), история, клавиатура, траектория.
- **Инструменти:** таблица до 255 инструмента (редакция с докосване), магазин карусел (до 6 колела), верига или линеен, автоматична и ръчна смяна, измерване с toolsetter.
- **Офсети:** G54–G59, отметнатите G55–G59 се изработват с една програма по инструмент; цикли с 3D пробника, калибриране в пръстен, карта на височините с корекция на Z.
- **Диагностика:** енкодери и следяща грешка, системни входове/изходи, аналогови канали с граници, 32 + 32 входа и изхода (ръчно включване), връзка с MCU.
- **Настройки:** вход с PIN по нива (по подразбиране 1111 Настройчик, 2222 Производител), всички раздели от макета, „Запиши“ / „Отмени промените“, дневник. Записват се в `~/.config/cnc-ui.conf` (или `$CNC_UI_CONF`).
- **Програми:** вградените примери и файловете от `~/cnc-programi` (или `$CNC_PROG_DIR`), USB (`/media/...`), мрежов дял (`/mnt/cnc-net`); 3D преглед, „Зареди“, „Изпълни от ред…“.

Още няма: екраните за лазер, плазма и струг (видът се избира в Настройки → Машина), собствен DRM драйвер за резолюция и завъртане, истински интерпретатор и връзка със STM32.

Опции на двете цели: `--prog файл.nc` зарежда програма вместо демото. В симулатора `--run` прави RESET и пуска програмата, когато машината е готова:

```sh
SDL_VIDEODRIVER=dummy ./build/cnc-ui-sim --res 1920x1200 --run --after 12000 --shot rabota.bmp
SDL_VIDEODRIVER=dummy ./build/cnc-ui-sim --res 1920x1200 --screen tools --shot instrumenti.bmp
SDL_VIDEODRIVER=dummy ./build/cnc-ui-sim --reset --after 9000 --act tc:10 --act cyc:z --screen probe --shot ofseti.bmp
```

`--screen` отваря екран (run jog mdi tools probe diag set files). `--act` е тестово действие (виж `ui_test()` в `src/ui.c`); действията се изпълняват едно след друго, когато машината е свободна. `--conf файл` чете и записва настройките (без него симулаторът започва със стойностите по подразбиране).
